# Deployment — Atlas + Render + Vercel

About 20 minutes. Do the steps in this order, because each one needs a URL from the step before it.

## 1. MongoDB Atlas (database)

1. Create a free **M0** cluster at https://cloud.mongodb.com (region: Mumbai `ap-south-1` is closest for Indian users).
2. **Database Access** → add a user with a strong password (role: *Read and write to any database*).
3. **Network Access** → add `0.0.0.0/0`. Render's free tier has no fixed IP, so access is protected by the password instead.
4. **Connect → Drivers** → copy the connection string and add the database name:
   `mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/maykraft?retryWrites=true&w=majority`
   URL-encode special characters in the password (`@` → `%40`).

## 2. Render (API)

1. Push the repo to GitHub.
2. On https://render.com → **New → Blueprint** → pick the repo. Render reads `render.yaml` and creates `maykraft-api` with `rootDir: server`.
   *(Or set it up by hand: New → Web Service, Root Directory `server`, Build `npm ci`, Start `npm start`, Health check `/api/health`.)*
3. Set these environment variables:
   | Key | Value |
   |---|---|
   | `NODE_ENV` | `production` |
   | `MONGO_URI` | your Atlas string |
   | `JWT_SECRET` | generated by the blueprint, or any 40+ character random string |
   | `CLIENT_URL` | leave as `https://example.com` for now; you'll fill it in step 4 |
4. Deploy, then open `https://<your-service>.onrender.com/api/health`. It should return `{"data":{"status":"ok",…}}`.
5. **Seed the database once** (optional, loads the demo accounts). On your machine:
   ```bash
   cd server
   MONGO_URI="<atlas string>" NODE_ENV=development npm run seed
   ```
   The seed refuses to run when `NODE_ENV=production` unless you pass `--force`. This guards against wiping real data.

> The free Render tier sleeps after 15 minutes idle, so the first request after that takes about 30–50 seconds. Open the health URL a minute before a demo.

## 3. Vercel (frontend)

1. On https://vercel.com → **Add New → Project** → import the repo.
2. **Root Directory:** `client`. Framework preset: **Vite** (build `npm run build`, output `dist`).
3. Environment variables:
   | Key | Value |
   |---|---|
   | `VITE_API_URL` | `https://<your-service>.onrender.com` (no trailing slash, no `/api`) |
   | `VITE_SHOW_DEMO` | `true` for a demo, `false` for real use |
4. Deploy. `client/vercel.json` sends every route to `index.html`, so refreshing `/manager/clients` works.

## 4. Connect the two

Back on Render, set `CLIENT_URL` to your Vercel URL, e.g. `https://maykraft.vercel.app`.
To allow preview deployments too, list them separated by commas:
`https://maykraft.vercel.app,https://maykraft-git-main-you.vercel.app`

Render redeploys by itself. Then:

- [ ] Landing page loads with the logo and three role cards
- [ ] Manager login works and the dashboard shows data
- [ ] Top bar shows **Live** (the socket is connected)
- [ ] A chat message from the manager appears instantly in the editor's open chat

## Troubleshooting

| Symptom | Fix |
|---|---|
| CORS error in the browser console | `CLIENT_URL` on Render must match the Vercel origin exactly (https, no trailing slash) |
| Top bar says **Offline** | Wrong `VITE_API_URL`, or Render is still waking up |
| `MongoServerError: bad auth` | Wrong Atlas password or not URL-encoded |
| Login gives 429 | The rate limiter (20 tries per 15 minutes per IP) is working; wait or redeploy |
| 404 on page refresh (Vercel) | Make sure `client/vercel.json` was deployed and the root directory is `client` |

Secrets live only in Render and Vercel settings. `.env` files are git-ignored, and only the `.env.example` files are committed.
